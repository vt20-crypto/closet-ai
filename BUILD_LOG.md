# BUILD_LOG

One short entry per task: date, what was built, which Meta models it uses.

- 2026-10-30: foundation. Next.js (App Router, TS, Tailwind) scaffold; `lib/meta/client.ts` shared Meta client; `GET /api/health` calling `muse-spark-1.3` (reasoning effort low, 60 s in-memory cache); `/capture` page (rear-camera file input, client-side resize to max 1600px JPEG, direct-to-Blob upload under `photos/`, grid persisted via blob listing); home page with health status. - 2026-11-02: capture pipeline. `lib/meta/sam.ts` (sam-3.1 segment + segmentGarments, 14 nouns parallel, cookbook stream-event shim, 429 backoff); `lib/cutout.ts` (hole fill + alpha cutout + union raster) with `lib/cutout.test.ts`; `lib/filters.ts` (confidence/area/dedupe/footwear-merge) with `lib/filters.test.ts`; `lib/meta/spark.ts` tagGarment (strict json_schema, pair hint, 429/400 handling); `lib/closet.ts` per-item Blob storage (`items/`, `candidates/`); routes `POST /api/segment` (maxDuration 120, per-step timing logs), `POST /api/closet/confirm`, `GET /api/closet`, `DELETE` item + candidate; `/capture` sequential auto-segment with Keep/Discard/Keep all on checkerboard cards + aria-live progress; `/closet` grid grouped by type with details + delete; home links to `/closet`. Meta models used: SAM 3.1, Muse Spark 1.3.
- 2026-11-02: daily outfits. `lib/outfits.ts` (category normalization, code-counted coverage, whole-outfit ID/completeness validator) with `lib/outfits.test.ts`; `lib/weather.ts` (Open-Meteo geocode + daily forecast, null on any failure); `lib/meta/spark.ts` gains `fetchDressCode` (separate web_search call, 10s timeout, URL from url_citation only) and `pickOutfits` (no tools, strict json_schema); `/api/outfits` (maxDuration 60, timings-only logs, coverage gate, one validation retry, session exclusion); `/today` page (chips, geolocation + city, 1–3 collages, shuffle, missing-coverage guidance with /capture link, en-US °F display); home links to `/today`. Meta models used: Muse Spark 1.3.
- 2026-11-02: unscanned-photo backlog. `lib/photos.ts` (`photos-meta/<photo>.json` scan records: scannedAt/candidateIds/keptIds, `photos/`-only pathname validation) with `lib/photos.test.ts`; `/api/segment` now takes `{ photoPathname }` resolved via `head()` in our own Blob store (arbitrary URLs rejected); `POST /api/closet/confirm` appends kept item ids to the photo meta; `GET /api/photos` returns the meta map and `DELETE /api/photos` removes the photo blob + meta (kept items untouched); `/capture` splits "Not scanned yet" (Find clothes per photo, Scan all sequential) from "Scanned" (N items kept, Scan again) with per-photo Delete.
